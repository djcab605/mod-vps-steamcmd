# 饥荒服务器配置：按人数和 MOD 挑机型，含洞穴双世界开服要点与端口避坑

租了台服务器准备和朋友开荒，结果人一多就开始飘、MOD 一装就掉线、洞穴开了连地面一起卡——这类问题十次里有八次不是"配置不够"，而是配置买错了地方。饥荒联机版对硬件的要求其实很低，但它的要求很偏，偏到你用一套"看核数、看内存总额"的通用思路去挑机器，很容易花冤枉钱。

下面把配置这件事拆开讲：饥荒到底吃什么、不同玩法规模该配什么、买机器时哪些参数才是关键，以及租云服务器开服最容易卡在哪一步。

## 先说结论：饥荒吃的是单核主频

饥荒联机版的服务端结构决定了它不是一个能"多核并行"的游戏。一个世界（一个地面世界或一个洞穴世界）基本由一个核心扛下来，主频越高，同屏生物、复杂地形、大型 MOD 脚本的处理就越稳。

由此推出三条实用规则：

**一个世界一个核。** 只开地面世界，1 核能跑；但正常玩基本都是"地面 + 洞穴"两个世界，那就至少要 2 核。想开双层世界（双地面 + 双洞穴），核心数直接翻到 4 核。

**主频比核数更值钱。** 同样是 2 核，一边是 2.5GHz 的老平台，一边是 5GHz 以上的高频 U，人少的时候看不出差别，人一多、天数百日、MOD 堆起来之后差距就很明显。

**内存决定你能装多少 MOD。** 2G 内存只能应付少量轻量 MOD，还得配虚拟内存兜底；想上永不妥协、棱镜勋章这类大型主题 MOD，4G 起步才比较踏实。而且饥荒的内存占用是随着天数增长的，存档跑得越久，吃掉的越多。

## 带宽和端口：配置够了还是连不上，八成卡在这里

带宽方面，饥荒的流量很小。3M 上行能撑住小队联机，5–10M 比较从容，20M 已经属于"给多开服务器留余量"。注意是**上行**，家里 500M 宽带的下行数字对开服没意义，很多家用宽带上行只有 20–30M，还要和全家的视频、下载抢。

端口才是真正的翻车高发区：

- **UDP 10999** —— 游戏连接的主端口，玩家就是连这里
- **UDP 10998** —— 洞穴世界用
- 部分环境还需要放行 **UDP 8767**（Steam 连接）

关键在 UDP。不少人做端口转发或者配置云服务器安全组时，顺手只加了 TCP 10999，结果服务端日志看起来一切正常，客户端却永远卡在"正在连接"。因为饥荒的通信走 UDP，TCP 那条规则根本没用。另外，Windows 服务器除了安全组，还要在系统防火墙的入站规则里单独放行一次。

如果你买的是 NAT 类型的云服务器（共用公网 IP、靠端口映射对外），还要把 NAT 映射的端口和服务器配置文件里的端口对齐，两边不一致同样连不上。

## 本地电脑、面板服、云服务器，怎么选

三种路线的差别很实际，不是价格高低的问题：

**家用电脑 + 内网穿透。** 成本最低，但要有公网 IP，或者忍受 FRP／虚拟局域网带来的额外延迟；电脑不能关，宽带一断人就全掉线。

**淘宝面板服。** 网页点点就能开，适合完全不想碰命令行的玩家。代价是没有 SSH 权限，服务端文件、MOD 配置都改不深，而且是共享机器，高峰期容易卡。

**自己的 VPS。** 有 root 权限，服务端文件随便改，MOD 想怎么配怎么配，玩腻了同一台机器还能开 MC、泰拉瑞亚。代价是要自己动手搭一次。开荒群里能长期稳定跑下去的方案，绝大多数都是这一类。

## 在 VPS 上把饥荒服跑起来的大致流程

不同教程细节有差异，主流程是统一的，按顺序走基本不会出岔子：

1. **买机器、选系统。** 系统建议 Ubuntu 20.04 或 22.04，对 SteamCMD 兼容性最好。内存吃紧的话顺手开一个 2G 左右的 swap。
2. **开端口。** 在雨云控制台把 UDP 10999、10998 放行或做 NAT 映射，别只加 TCP。
3. **装 32 位运行库。** 饥荒服务端是 32 位程序，64 位 Linux 上必须补依赖，否则服务端根本起不来：

bash
sudo apt update
sudo apt install -y libstdc++6:i386 libgcc1:i386 libcurl4-gnutls-dev:i386


4. **装 SteamCMD 并下载服务端。** 饥荒专用服务端工具的 app id 是 343050：

bash
mkdir -p ~/steamcmd && cd ~/steamcmd
wget "https://steamcdn-a.akamaihd.net/client/installer/steamcmd_linux.tar.gz"
tar -xvzf steamcmd_linux.tar.gz
./steamcmd.sh
# 进入 steamcmd 后：
login anonymous
force_install_dir ~/dontstarvetogether_dedicated_server
app_update 343050 validate
quit


5. **拿服务器 token。** 这一步不能省。在装了游戏客户端的电脑上打开饥荒联机版，进"账号 → 游戏 → 《饥荒：联机版》的游戏服务器"页面，新建或复制一个服务器凭证；也可以在游戏里按 `~` 打开控制台执行 `TheNet:GenerateClusterToken()` 生成文件。把内容保存成 `cluster_token.txt`。
6. **上传存档。** 在本机创建好世界（起个容易认的名字），把整个 Cluster 目录连同 `cluster_token.txt` 一起传到服务器的 `~/.klei/DoNotStarveTogether/` 下。用 VSCode 的 Remote SSH 直接拖，比 scp 命令省事。
7. **后台常驻。** 用 `screen` 或 `systemd` 挂起来，否则一断开 SSH 服务端就没了：

bash
cd ~/dontstarvetogether_dedicated_server/bin
screen -S dst ./dontstarve_dedicated_server_nullrenderer -console


按键 `Ctrl+A` 再按 `D` 退出会话，服务端继续跑。

8. **配 MOD。** 在服务端的 `mods` 目录下编辑 `dedicated_server_mods_setup.lua`，用 `ServerModSetup("workshop-xxxxxx")` 按 workshop ID 声明需要的 MOD（整包订阅用 `ServerModCollectionSetup`）；再用 `modoverrides.lua` 控制哪些 MOD 真正启用、参数怎么设。注意"下载"和"启用"是两件事，光下载不会生效。

## 开服之后才会遇到的那几个坑

**连不上、一直"未响应"。** 排查顺序固定：先确认 UDP 10999 真的通（服务器上看 `netstat -an` 有没有监听），再看内存，最后看 MOD。

**进程还在，但客户端连不上，服务器 CPU 占用掉到几乎为零。** 这通常是物理内存被两个世界进程吃满、开始疯狂读写 swap 导致的假死。能连上控制台的话先执行 `c_save()` 强制存一次档，再重启进程。长期解决办法是加内存，或者减少大型 MOD。

**地面和洞穴互相拖累。** 两个进程默认会争抢同一个核心，表现为随机卡顿。可以给两个进程分别绑定不同的 CPU 核心，或者干脆把洞穴拆到另一台机器上跑。

**游戏一更新，服务器就搜不到了。** 饥荒服务端不会自动跟着更新，每次游戏版本更新后都要手动执行一次 `app_update 343050 validate`，不然玩家版本对不上，自然进不来。

**MOD 冲突导致启动卡死。** 新 MOD 跟不上游戏版本时，加载报错但不退出，连接流程就卡在验证那一步。做法是把 MOD 先全关、裸启动确认没问题，再一个个加回来，每加一个重启一次看日志，用时间换准确。
